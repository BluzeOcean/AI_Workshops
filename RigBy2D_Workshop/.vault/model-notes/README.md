# `model-notes/` — what works on this machine

Notes about RigBy2D itself: which version, which settings, what it is good for. Text
only — the app and its add-ons live in their own install directories.

```
model-notes/YYYY-MM-DD-<topic>.md
```

Useful things to record here:

- A version, an add-on or a plugin, and what it works with.
- The install path, and the **rule for resolving the newest one** rather than pinning it.
- Which control surfaces exist — CLI, API, plugin, headless mode — and what each one can
  actually do.
- The **literal** shape of a request and a response, as probed. Not a description of the
  protocol from memory.
- Settings that produced a good result.
- Export or publish settings that a downstream tool accepted without complaints.

Record the version in every note. These are versioned facts, and they expire — mark them
`Status: stale` with the date they stopped applying rather than rewriting them.
